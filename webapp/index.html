An .oap package is a signed, tamper-evident archive holding actor reference portraits, visual traits, and content riders. Inspect packages before importing to verify digital signatures and rider rules.
 
ℹ️ Trust confirmation: A valid cryptographic signature proves the package was not altered and confirms author provenance, but does not equal endorsement. Confirm you trust this creator before importing.


Role agreements
Cast an actor for a role with an OAP 0.5 agreement bound to the actor's exact signed manifest and your casting call. This studio signs as Director; the actor's Agent countersigns with their own key. Terms are fixed once drafted. Agreements record consent; they do not approve rider exceptions or make payments.
Draft an agreement
Import a countersigned agreement
Download an agreement bundle and send it to the Agent. When they return their signed agreement.json, import it here. Only valid signatures on unchanged terms are accepted.


Open Prop Protocol library
Inspect and import a .opp prop package. Props stay in this studio and do not become OAP actors. The bundled guitar and keyboards are installed here as props; choose any imported prop for an instrument in the video form.

    STUDIO ACTORS & OPEN ACTOR PROTOCOL
    How Cast, References & OAP Work
    🎭 Characters vs. Scene Reference Images
    🎭 Cast (Actors & Props)
    Use for: Recurring people, singers, bands, or performers.
    • Portrait binds to generation pipeline slots (e.g. <Picture 1>).
    • Visual traits and description guide the prompt writer.
    • Actor safety riders dictate allowed content ratings and themes.
    • Created or imported in 03. Actors & Props.
    🖼️ Additional Reference Images
    Use for: Environmental lighting, color palette, or set design.
    • Attached directly in 01. Music Video (up to 9 images).
    • Guides visual style, camera atmosphere, and lighting aesthetics.
    • Does NOT anchor character identity or facial likeness.
    • No safety rider bindings attached.
    📦 What is Open Actor Protocol (.oap)?
    Open Actor Protocol (OAP) is an open specification for portable, consent-driven digital actor identities across modern AI production tools.
    • Self-Contained Packages: An .oap file is an archive containing reference portraits, character descriptions, and safety metadata.
    • Portability: Move actors between Mondo Music Video, ComfyUI, 3D pipelines, and other studios without recreating prompts from scratch.
    • Exporting: You can export any actor in your cast as a signed .oap package to share or archive. The reference image in a full export is not encrypted, so anyone who receives the file can open it.
    • Strict Package Sandboxing: Mondo protects against zip-slip and path traversal attacks, and normalizes portraits to clean RGB images stripping dangerous EXIF data.
    🔐 Signatures & Why We Ask About Trust
    When you inspect an .oap package, Mondo checks its Ed25519 digital signature and file checksums.
    Why "A valid signature does not establish trust"?
    A cryptographic signature proves integrity (the package was not altered since export) and provenance (the public DID of who signed it). However, anyone can generate a keypair. The signature alone cannot verify whether the signer has rightful authority to distribute that person's likeness. You, the operator, must confirm that you trust the creator or agency before importing.
    What is "Allow unsigned"?
    Older OAP 0.3 or earlier packages might not have an Ed25519 signature. Checking "Explicitly allow an unsigned package" lets you test one locally. OAP 0.4 and newer packages must always be signed.
    What are sealed packages?
    An Agent can encrypt an actor's reference so only one studio can open it. To receive one, send them the key from Show this studio's recipient key in 03. Actors & Props. A package sealed to another studio can be inspected but not imported.
    What is revocation?
    A signer can publish a signed notice that their key should no longer be trusted. If a package carries that notice for the key that signed it, Mondo refuses the package even though the signature itself is valid.
    🛡️ Safety Riders & Content Consent
    Actors have rights over how their likeness is represented. OAP packages include an immutable Rider with explicit content boundaries across 4 dimensions:
    • Nudity: none | implied | explicit
    • Sexual Content: none | implied | explicit
    • Blood & Gore: none | mild | graphic
    • Violence: none | action | graphic
    Automatic Upstream Enforcement:
    Before any production preview or generation starts, Mondo's check_cast() engine compares your video's requested rating ceiling against every selected actor's rider. If a video requests graphic violence but an actor only allows action, generation is blocked immediately.
    ⚙️ Pipeline Execution & Studio Isolation
    How your cast flows from musical analysis into final video frames:
    • Casting Policies: Choose how actors are assigned across passages: random (seeded variation), rotate (sequential cycling), or section (holding actor focus through an entire verse or chorus).
    • Ensemble Modes: Set whether frames feature solo actors (off), mix solo verses with ensemble peaks (mixed), or share every frame (always).
    • Writer Continuity: Prompts bind characters to <Picture 1>, <Picture 2> tags under a strict physical continuity contract.
    • Zero External Execution: Foreign packages containing voices, weights, or external scripts are safely preserved in original.oap for round-trip export, but are never executed as executable code.

    Launch command preview
    



    Context and memory
    A llama.cpp launch command is a JSON array: one executable path followed by individual arguments. Keep your existing model path and alias. The -c argument sets context size; a larger context uses more memory. Choose a value supported by your model and GPU. Batch and micro-batch sizes also affect memory use; tune them deliberately rather than copying another machine's settings.
    

    Vision and service URLs
    Style Harvest needs a vision-capable service. If your model needs a projector, load its matching --mmproj file. Image-token options vary by model and llama.cpp version. Use the OpenAI-compatible base URL, usually ending in /v1; MMV appends /chat/completions for generation and /models for health checks.
    

    The Windows launcher accepts -ContextSize to choose a context size. This does not replace the current model. Check the service log for startup errors before increasing memory settings.
